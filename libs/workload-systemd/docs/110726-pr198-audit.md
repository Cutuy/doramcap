## Findings

- **F1 / P1 — Track units before submitting start jobs.** `running.rs:52-63` pushes each Unit only after `start_program`/`start_adopted` returns; `manager.rs:129,176` waits for the job before returning. A readiness timeout or stop during a long start drops the only handle. `stop` sees an empty group and reports writers stopped; shared finalization runs before slice reset. Native reproduction with a two-second readiness budget and a long-running adopted oneshot observed `FinalizeRecordings` while its PID was alive: report says writers_stopped=true, recording_finalized=true, units=0. Cleanup subsequently succeeded. Preserve attempted ownership before cancellable effects and verify quiescence before finalizing.
- **F2 / P2 — Submit same-group starts before awaiting completion.** `systemd_plan.proto:11` promises units start together, but `running.rs:52-63` awaits each start job serially. An adopted oneshot/notify service waiting on a later peer never allows that peer's start request; the group times out. Static trace; no native paired-service reproduction run.
- **F3 / P1 — Resolve or reject references before renaming adopted services.** `manager.rs:140-161` copies `a.service` to a repository-prefixed name and changes only Slice. A `Requires=b.service` reference still targets the original host name rather than the adopted copy. It can fail to start or start a host unit outside the owned slice. The plan's M3 spike explicitly says repository references must be rewritten or rejected; validate never reads the file. Static evidence; host dependency launch was not exercised. Owner selected rejection of unsupported references before side effects; implementation is pending.
- **F4 / P2 — Propagate runtime cleanup errors before verifying removal.** `manager.rs:224-238` ignores read_dir errors, DisableUnitFiles errors and both remove_dir_all results. A failed removal of a drop-in can leave runtime files while the subsequent loaded-unit query is empty; cleanup_verified can become true. Loaded units do not prove filesystem cleanup. Propagate errors except explicit absent-path cases and verify owned artifacts. Static error-path trace; filesystem fault injection not run.
